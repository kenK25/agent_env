# model-router（Claude Code版）

目的: メイン会話（高コストモデル）の消費を最小にし、作業の大半を安価なモデルの隔離コンテキストで処理する。

## 発火条件（これ以外では使わない）
- 使う: 2ファイル以上の調査／2ファイル以上の生成・変更
- 使わない: 単発の質問、1ファイルだけの修正、対象ファイルが特定済みの小修正

## 手順（必ずこの順で）

### 1. タスク分析（メイン会話で行い、出力は10行以内）
依頼を次の4種類のサブタスクに分ける。
- **探索 (explore)**: ファイル検索、grep、構造把握、ログやビルド出力の読み取り
- **収集 (collect)**: 資料・論文・データシート・Web/HFからの事実抽出と要約
- **生成 (generate)**: コード実装、設定ファイル、ドキュメント草稿
- **判断 (reason)**: アーキテクチャ選定、セキュリティ設計、トレードオフ評価、最終レビュー

分解結果を次の表で1回だけ示し、ユーザーの確認を待たずに続行する（「判断」が2つ以上あるときだけ一言確認する）。

| # | サブタスク | 種別 | モデル | 入力 | 返す成果物 |

### 2. モデル割当（`.claude/skills/model-router/references/routing.md` の規則に従う）
既定: explore=haiku / collect=haiku / generate=sonnet / reason=メイン会話のモデル。

### 3. サブエージェント起動（Claude Code の Agent tool）
- `model` パラメータを必ず明示する（`"haiku"` / `"sonnet"` / `"opus"`）。継承に任せない。
- explore は `subagent_type: "Explore"`、それ以外は `general-purpose` を使う。
- 各サブエージェントへの指示に必ず入れるもの: 対象パス、禁止事項（全文readの禁止、vendor/build除外）、**返却形式**（結論のみ／最大N行／ファイルパス＋行番号）。
- 関連するサブタスクは1体にまとめる。1体ごとに初期化コストがかかるため、5体以上に分けない。
- 依存関係のないサブタスクは、1メッセージ内で並列に起動する。

### 4. 統合（メイン会話）
- サブエージェントの返却物は要約で受け取り、生データをメインに貼らない。
- 「判断」だけをメイン会話で行う。
- 終了時の記録は session-close に任せる。

## 禁止事項
- メイン会話でリポジトリ全体や SDK/vendor ディレクトリを直接読むこと
- 探索・収集をメイン会話のモデルで行うこと
- サブエージェントに範囲を指定せず「全部調べて」と投げること
