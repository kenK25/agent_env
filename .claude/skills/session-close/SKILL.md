# session-close（Claude Code版）

目的: 自動圧縮で文脈が消える前、またはクラウドのコンテナが回収される前にディスクへ退避し、次のセッションの bootstrap が1ファイルで復元できる状態にする。

## 発火条件（これ以外では使わない）
- 使う: 2ファイル以上の調査／2ファイル以上の生成・変更が、一区切りしたときや終わるとき
- 使わない: 単発の質問、1ファイルだけの修正、対象ファイルが特定済みの小修正

## 手順

### 1. 書く内容を分類
このセッションで起きたことを次のように振り分ける。
- **ADR**（設計・セキュリティ・モデル選定レベル）: 決定／理由／却下案 の3項目。1件5〜8行。
- **細かい決定**: 1行。
- **未完タスク**: チェックボックス。
- **接続・参照先**: **値は書かない。** 参照名だけ（sshのhost名、環境変数名、ファイルパス）。
- **見積 vs 実績**: token-estimate を使っていれば1行追記。

### 2. 秘密値チェック（必須）
書き出す前に次を通す。
```
python3 .claude/skills/session-close/scripts/check_secrets.py <file>
```
検知した行は書かず、ユーザーに「参照名に置き換えてよいか」を確認する。
検知対象: API key / token / password / private key / 接続文字列（`://user:pass@`）/ 長いbase64風の文字列。

### 3. タスクノートを更新
`notes/[task].md` の該当セクションに追記する（上書きしない）。ADR番号は、**索引 session-notes.md の「直近の決定事項」に載っている全ADRを通した連番**にする（タスクノートの中で独自に採番しない）。新規タスクノートでも 001 から始めず、索引の既存最大番号+1 から始める。索引が空のときだけ 001 にする。

### 4. 索引を更新
`session-notes.md` について、
- タスク索引行の「状態」「最終更新」を更新する
- 「直近の決定事項」にADRの見出しを追加する（最新5件を保ち、あふれた分は削除する）
- 「見積補正メモ」に、必要なら1行追加する
索引が50行を超えたら、完了タスクの行を `notes/archive/` に移し、索引から削除する。

### 5. commit・push（Code版で追加した手順）
クラウドのセッションはコンテナが回収されるため、`session-notes.md` と `notes/` を作業ブランチに commit し、push する。コミットメッセージは `notes: <task> のセッション記録を更新` とする。

### 6. 確認出力（5行以内）
「書き出した項目数（ADR n件／未完 n件）」「ファイルパス」「秘密値の検知の有無」「commitのハッシュ」を報告する。次のセッションの再開方法は「`session-notes.md` を読んで続き」の一文で済むことを示す。

## 禁止事項
- 会話ログの転記（要約ではなく逐語で書くこと）。ノートは次回読むたびにコストになる
- 秘密値の書き込み
- 1タスクのノートが300行を超えること（超える場合は `notes/[task]-part2.md` に分割する）
